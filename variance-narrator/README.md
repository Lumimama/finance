# Variance Narrator

Turns a budget-vs-actuals export into the variance commentary that goes in front of a CFO or a board.

The math in a month-end variance review is deterministic. The writing is not — it's twenty paragraphs of *"hosting came in $177K over plan, driven by…"* that get rewritten from scratch every month, and it's the part that eats a Thursday. This splits the job along that line:

- **Python does the analysis.** Variance, direction, materiality, rollups. Every number in the output is computed here.
- **Claude drafts the narrative** from that computed evidence pack.

The model never does arithmetic and never sees a figure it wasn't handed. That constraint is the whole design — a variance report that hallucinates a number is worse than no report, and the only reliable way to prevent it is to make sure the model has nothing to hallucinate *from*.

## Run it

```bash
pip install -r requirements.txt
python variance_narrator.py --dry-run
```

`--dry-run` prints the full analysis and the exact prompt that would be sent, and makes no API call. That's the default way to look at this repo — the analysis is the part you'd want to audit, and you shouldn't need a key to audit it.

To draft live commentary:

```bash
export ANTHROPIC_API_KEY=sk-ant-...
python variance_narrator.py --period 2026-03 --out commentary.md
```

Other flags:

```bash
python variance_narrator.py --threshold-usd 50000 --threshold-pct 0.15
```

[`examples/dry-run-2026-03.txt`](examples/dry-run-2026-03.txt) is the real output of the dry-run command against the committed data.

## What it computes

```
==============================================================================
VARIANCE ANALYSIS  |  2026-03
==============================================================================
                                Budget        Actual      Variance         %
------------------------------------------------------------------------------
Revenue                     $3,290,000    $3,470,500      $180,500     +5.5%
Cost of revenue               $768,300      $945,080      $176,780    +23.0%
Operating expense           $3,615,000    $3,611,153       -$3,847     -0.1%
------------------------------------------------------------------------------
Gross profit                $2,521,700    $2,525,420        $3,720
  gross margin                  76.6%         72.8%
Operating income           -$1,093,300   -$1,085,733        $7,567

Material variances  (6 of 18 lines cleared both $25,000 and 10%)
------------------------------------------------------------------------------
  [UNF] Cost of revenue  Hosting & infrastructure           $176,877    +43.1%
  [FAV] Marketing        Paid acquisition                  -$138,932    -42.1%
  [FAV] Engineering      Engineering payroll               -$128,670    -10.7%
  [UNF] G&A              Professional fees                  $113,247   +103.0%
  [UNF] Engineering      Contractors                        $105,444    +87.9%
  [UNF] Sales            Commissions                         $47,024    +21.9%
```

That output is the interesting part of the month, and it's six lines out of eighteen. Two decisions get it there.

**Materiality is a dual test.** A line surfaces only if it clears both an absolute threshold and a percentage one. Screening on percentage alone floods the report with $3K office-supply lines that moved 40%; screening on dollars alone buries a small account that quietly doubled. Neither test is useful without the other.

**Direction depends on the account.** Over budget is good news on revenue and bad news on spend, so favorability is derived from `account_type` rather than from the sign of the variance. This is the most common bug in a home-grown variance report — it produces commentary that congratulates the team for overspending.

Note that "favorable" here is a P&L convention, not a business judgment. Paid acquisition landing 42% under plan is favorable to operating income and may well be terrible for next quarter's pipeline. The commentary is written to surface that tension rather than paper over it.

## What the drafted commentary does and doesn't claim

The dataset contains variances. It contains no *causes* — nothing in a GL export tells you why hosting spiked. So the system prompt forbids inventing drivers. Where a cause would normally go, the draft states the observable fact and routes the question to the department owner under an **Open items** heading.

This is the difference between a tool that saves you an afternoon and a tool you have to fact-check line by line. The draft is a first pass with the arithmetic already correct and the open questions already flagged — not a finished document, and not pretending to be one.

## Data

Fully synthetic. Generated by [`make_sample_data.py`](make_sample_data.py), seeded, reproducible. The shape is realistic for a roughly $40M ARR B2B software company — department structure, account taxonomy, the relative size of the variances — but no figure comes from any real company.

To point it at your own export, match the schema in `data/budget_vs_actuals.csv`:

| column | notes |
|---|---|
| `period` | `YYYY-MM` |
| `department` | rollup key |
| `account` | GL account name |
| `account_type` | `revenue`, `cogs`, or `opex` — drives favorability |
| `budget` | |
| `actual` | |
